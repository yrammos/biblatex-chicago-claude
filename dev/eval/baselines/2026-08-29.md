# Baseline — 2026-08-29

The first two full runs of the 61-entry sample (2026-08-28 and this one) are
not comparable: between them, three sources gained a working OCR path
(missing tesseract language packs, `deu`/`rus`), `run.py` stopped swallowing
a failed extraction's own error message, and two `expected.bib` typos
(Drabkin1983, Dunsby2020) were corrected. Run 1's 46/61 measures a system
that no longer exists. This run - the first against the corrected harness
and the corrected ground truth - is the baseline going forward.

## Delta against run 1 (2026-08-28, unrecorded)

Run 1 scored 46/61 (75%) against 15 wrong-type entries, three of which
(Menke2004, Motte2004, Rimsky1952) produced no entry at all. All four
resolved without regression - no entry correct in run 1 came back wrong here:

| Citekey | Run 1 | Run 2 (this baseline) |
|---|---|---|
| Menke2004 | `(no entry produced)` — missing tesseract `deu` data | correct |
| Motte2004 | `(no entry produced)` — missing tesseract `deu` data | correct |
| Rimsky1952 | `(no entry produced)` — missing tesseract `rus` data | correct |
| Gollin2011a | `suppbook` → `inbook` | correct |

Gollin2011a's fix isn't attributable to any change made between the two runs
(none touched suppbook/inbook classification) - most likely run-to-run
extraction variance, not a fix. The other three follow directly from the
tesseract-lang install (see the diagnostic `--only` runs of 2026-08-29).

**The +4 is the whole improvement.** The other 11 wrong-type entries are not
merely "still wrong" - they are identical to run 1, entry for entry, both
citekey and the specific expected/produced pair:

## Author field: a second, smaller unexplained regression

`author` moved 35 exact → 33 despite three new entries existing that didn't
in run 1 - the only field to move against expectation; every other field
held or improved. Investigated with `--rescore` (`dev/eval/last-run/` against
`expected.bib`; no API calls):

- **Menke2004** (new entry, run 1 had none): `missing` → `different`.
  Expected `Menke, Johaness`; produced `Menke, Johannes`. Reads as a second
  ground-truth typo (a missing `n`, alongside Drabkin1983/Dunsby2020) rather
  than a pipeline error - flagging, not correcting, per the maintainer-only
  rule above.
- **Rimsky1952** (new entry): `missing` → `missing`, unchanged. OCR now runs
  (1,044 words) but still yields no author.
- **Gollin2011a** (type now correct, `suppbook`): author is `missing`
  (`produced: None`) against expected `Gollin, Edward and Rehding,
  Alexander` - the volume's editors, credited as the entry's author because
  this is a glossary contribution with no individually credited author. The
  produced entry has `date`/`location`/`publisher`/`title`/`pages` but no
  author at all, which is the container/contribution pattern of #14 again:
  the editors' names are container-level information (the book's title page,
  not the glossary's own pages).

These three account for at most 1 of the net -2 (Menke2004 leaves `missing`
without becoming `exact`; Rimsky1952 doesn't move; Gollin2011a's prior state
in run 1 is unknown, since run 1 predates any per-entry persistence - it may
have been `exact`, `different`, or absent from the count entirely). At least
one more entry, among the 57 whose type didn't change, must have left
`exact` between the two runs to reach 33. **It cannot be identified**: run
1's per-field values were never saved, only its aggregate counts and the
15-entry type-mismatch list, and finding it would mean re-extracting - which
this investigation was explicitly scoped not to do. Recorded as a second,
independent instance of run-to-run variance, on top of Gollin2011a's type
flip.

## Variance floor

**1 flip in 61 with no attributable cause: ≈1.6%.** Gollin2011a's entry type
changed between two runs of the identical pipeline against the identical
source, with nothing in between to explain it. That is the floor below which
this harness cannot resolve a real change from noise, and it is the
threshold every future comparison against this baseline should be judged
against - a shift smaller than this is not evidence of anything.

The `author`-field regression above is independent corroborating evidence
for the same conclusion, at a different granularity (a field flip rather
than a type flip, on an entry whose type didn't even change) - not a second
figure to add to the 1.6%.
