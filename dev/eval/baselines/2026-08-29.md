# Baseline — 2026-08-29

The first two full runs of the 61-entry sample (2026-08-28 and this one) are
not comparable: between them, three sources gained a working OCR path
(missing tesseract language packs, `deu`/`rus`), `run.py` stopped swallowing
a failed extraction's own error message, and two `expected.bib` typos
(Drabkin1983, Dunsby2020) were corrected. Run 1's 46/61 measures a system
that no longer exists. This run - the first against the corrected harness
and the corrected ground truth - is the baseline going forward.

## Delta against run 1 (2026-08-28, unrecorded)

Run 1 scored 46/61 (75%) against 15 wrong-type entries, three of which
(Menke2004, Motte2004, Rimsky1952) produced no entry at all. All four
resolved without regression - no entry correct in run 1 came back wrong here:

| Citekey | Run 1 | Run 2 (this baseline) |
|---|---|---|
| Menke2004 | `(no entry produced)` — missing tesseract `deu` data | correct |
| Motte2004 | `(no entry produced)` — missing tesseract `deu` data | correct |
| Rimsky1952 | `(no entry produced)` — missing tesseract `rus` data | correct |
| Gollin2011a | `suppbook` → `inbook` | correct |

Gollin2011a's fix isn't attributable to any change made between the two runs
(none touched suppbook/inbook classification) - most likely run-to-run
extraction variance, not a fix. The other three follow directly from the
tesseract-lang install (see the diagnostic `--only` runs of 2026-08-29).

The remaining 11 wrong-type entries are unchanged from run 1 and are the
subject of [#14](https://github.com/yrammos/biblatex-chicago-claude/issues/14)
(8 of them) and separately Ayrey2006, Hultqvistnodate, ScienceDirect0.
